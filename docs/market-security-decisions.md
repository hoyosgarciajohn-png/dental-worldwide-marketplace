# Marketplace engineering controls
November 5, 2026. Fictional implementation; no clinical/legal/live clearance.

- HTTP: exact configured loopback Host/scheme/Origin, no forwarded-header trust, HttpOnly same-site cookies, actual Auth getUser + DB current session for every protected operation. No service key in browser. Bounded 64KiB ordinary JSON and7MiB file base64 requests; no-store responses.
- Account changes: ordinary M1 and marketplace requests validate the presented bearer with the provider and use it for database operations. They never refresh the provider session or write/clear authentication cookies, including on failure. This prevents a delayed ordinary response from replacing a later account selection. Expired access requires explicit reauthentication in this local candidate. Cookie mutations are reserved for explicit sign-in, sign-out, MFA verification and password recovery; the UI serializes those actions. Production session-renewal design remains a separate review item.
- Files: max5MiB PDF/JPEG/PNG only, signature+MIME+extension verification, generated opaque immutable object keys, SHA256, private bucket with no ordinary direct policies. Quarantine by default; server-only simulated scan bridge in isolated tests. Unknown/timeout/rejected cannot download. Reauthorize before/after bytes retrieval and mutation retry; no signed links. Already-delivered bytes cannot be revoked.
- Rate limits: atomic authenticated account bucket120operations/minute and10file registrations/minute. Direct RPC shares checks. Values are development limits, not validated production capacity.
- Scope/grants: exact recipient site and categories, no admin blanket patient access. Staff current membership/write permissions and verified MFA; coordinator needs patient grant plus assignment. Suspension blocks new work; staff historical continuity requires separately recorded authorization and active grant. Withdrawal never silently reversed.
- Booking:60-minute slots, UTC instant plus IANA zone, latest immutable unexpired estimate accepted, patient acceptance of alternate time, current scope/grant at confirmation, optimistic versions and serialized conflicts. Actual attendance cannot predate schedule.
- Recovery: keep protected access closed while old authorization is restored. Reconcile every restored access-bearing record from trusted post-snapshot journal; missing history stays closed. Actual local rehearsal is not cloud PITR or whole-host disaster assurance. Measure local snapshot age and elapsed recovery separately; do not claim ongoing24hRPO/8hRTO without live operations.
- Monitoring: local readiness endpoint returns only ready state; dependency or closed-recovery gate yields503. Captured monitoring behavior only, no outbound alerts.
- Preview: static owner-private frontend simulation with fictional records, clearly browser-local. Connected backend mode requires actual approved local Auth/DB; no fake connectivity. No real verification, malware assurance, billing or message delivery.
- Human queue: manual assistive-tech/device/usability; practitioner/site/service acceptance; professional/privacy/contracts/retention; staffed support and clinical escalation; genuine market validation remain DEFERRED M7/NOT PERFORMED before corresponding real activity.
