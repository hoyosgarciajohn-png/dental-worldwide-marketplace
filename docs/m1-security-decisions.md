| M1-S07 database | Dedicated private schema, RLS default deny on every table, no ordinary direct table access. Privileged bootstrap via local test SQL only. | Ordinary user JWTs use actual Data API/RPC; direct table reads/writes and privilege mutation attempts denied; valid scoped RPC succeeds. | M1-S08 audit | Append-only security metadata with actor/action/object/result/time/correlation and organization scope; no passwords, token/links or clinical body. | M1-S09 browser/server | Same-origin BFF; access/refresh tokens in HttpOnly SameSite=Strict cookies; service key server-only. No client token storage. | M1-S10 recovery/cleanup | Password changes increment account security version and revoke application sessions at DB trigger. S11. Local provider limits allow the bounded 20-patient/five-practice test fixture (300 password requests/5 minutes, 100 captured emails/hour); the application gateway still enforces its own atomic 5/account and 20/loopback-peer attempts/15 minutes. Direct provider endpoints are loopback-only in this candidate. A public production network boundary and trusted proxy policy remain M7 prerequisites. Lost-factor reset records the old factor IDs; those factors cannot clear the pending-reset gate, even if provider deletion fails.

S12. Minimal export and deferred-execution fixtures return only synthetic authorization-test records. A queued fixture stores requester/record IDs and state, never a cached payload; executing it rechecks current session, account, membership, site, category, recipient grant and assignment. No production queue or clinical export module is built. UI private state is cleared on logout, account switch and invalid session.
